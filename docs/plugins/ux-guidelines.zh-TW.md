# UX 指南

插件在 Agent Pets 中如何呈現，以及使用者會看到的文字該怎麼寫。以下限制都來自 manifest 驗證器與 Host API。

## 使用者在哪裡遇到你的插件

一切都在**設定 → 整合與進階 → 插件**，分成四個分頁。

| 分頁 | 顯示你的插件的哪些資訊 |
|---|---|
| **已安裝** | 一張卡片：名稱、版本、作者、狀態，以及標示提供內容的標籤（面板、指令、Tray、徽章、寵物外觀、工作狀態、排程、通知、寵物反應）、啟用開關，還有「開啟插件面板」、「設定」、「詳情」按鈕。可搜尋與篩選（已啟用、有更新、需注意）。 |
| **探索** | 選擇啟用的線上目錄。卡片顯示目錄中的名稱、版本、大小與目錄的**說明**、已綁定簽章的標籤；ID、作者與金鑰指紋在「更多詳情」。 |
| **通知** | 你用 `api.feed.notify` 送出的所有項目，不論當下有沒有顯示氣泡。使用者可依插件篩選、全部標為已讀、清除某個插件的項目（可復原），並在詳情頁將插件靜音。 |
| **進階** | 開發者模式、資源限制與全域開關，與個別插件無關。 |

**詳情頁**有四個區段：**概覽**（通知路由：目標寵物、靜音與通知頻率；網路主機表，區分已宣告與已允許並可撤銷；以及「它在 App 中的出現位置」：Tray 項目、目前徽章文字、外觀、狀態列）、**設定**（你的 `settings` 表單）、**指令**（你的 `commands`）與**診斷**（你的紀錄與被拒絕的呼叫）。頁首顯示版本與簽章狀態。使用者也可以回報問題，或移除插件（可選擇一併刪除設定與資料）。

### 儀表板分頁

已啟用的插件也會在控制面板的「工作階段」「額度」「歷史」之後多一個自己的分頁。只有在插件功能全域開啟，且你的插件已安裝、已啟用、沒有當機時才會出現，任一條件不成立就會立刻消失。分頁顯示 manifest 的 `name`（太長會截斷）、你的 `icon`（沒有就用通用插件圖示），以及未讀通知數或 `badge` 文字的徽章。若你貢獻了 `panelView`，面板會嵌在分頁內，沿用與設定頁插件面板相同的外框、沙箱與尺寸規則；使用者切換分頁或隱藏面板時它就會關閉，所以請讓頁面能隨尺寸調整，且不要依賴兩次開啟之間的畫面狀態。沒有 `panelView` 的插件，分頁會顯示最近的通知與你的 `commands` 按鈕，並連到設定與詳情。

### 安裝畫面

安裝前會先顯示來源（目錄、本機檔案或開發資料夾）、版本變化、作者簽章狀態，以及每一項要求的權限，並**依風險分組**：「網路與外部連結」與「資料與密鑰」群組含高風險項目，儲存、排程與 Agent 狀態屬中風險，顯示類貢獻屬低風險。更新時，**新增的權限**會與既有權限分開列出。新增網路、連結或密鑰權限，或簽章金鑰變更／被移除，使用者必須勾選「我已了解這些變更」，且焦點一開始在取消。請事先規劃：更新時新增高風險權限會多一道關卡，盡量少做，並在發布說明中交代原因。

### Toast 與面板外框

Toast 由 App 繪製，用來確認使用者自己的操作（例如指令已送出、已撤銷某主機的存取、通知已清除），插件無法建立。你的通知走寵物氣泡與通知收件匣。

面板頁顯示在 Host 繪製的外框內：返回按鈕（Esc）、你的圖示、你的 `panelView.title`，其下是「插件名稱 · 版本」、簽章狀態、**重新載入面板**、前往該插件權限與設定的連結，以及**最大化**（按兩下標題列；Esc 還原）。載入中會顯示「正在載入…」，5 秒後提供取消；載入失敗則顯示重新載入、返回與回報按鈕。外框位置與「插件內容」標記都不能由插件修改。控制面板有一個所有畫面共用、使用者可自行調整的大小，開啟你的面板不會改變視窗大小，`preferredSize` 也不再影響它：請讓版面從 360 px 寬到全螢幕都能正常排列。

## 為人而寫

| 位置 | 規則 |
|---|---|
| `name` | 必須同時有 `zh-TW` 與 `en-US`，各 1–48 字元。用名詞，不要寫成句子；名稱中不放版本或「插件」。 |
| 目錄 `description` | 目錄索引中兩種語言都必填。用一句話說明對使用者的改變（「每 30 分鐘顯示一次休息提醒」）。這是使用者在安裝前唯一會看到的自由文字。 |
| `panelView.title` | 最多 48 字元。它是外框的標題，所以要說明這個頁面的用途。 |
| 指令 `title` | 最多 32 字元，用動詞片語（「現在提醒我」）。Tray 標籤為純文字，超過 32 字元會被截斷。 |
| 設定 `title` | 最多 48 字元，否則會顯示原始鍵名。單位寫進標題（「間隔（分鐘）」）。善用 `minimum`、`maximum`、`maxLength` 與 `enum`，讓表單替使用者驗證。 |
| `feed.notify` | 標題最多 60、內文最多 240。開頭先寫事件（「建置失敗」），不要寫插件名稱（來源會自動顯示）。輪詢的事件用固定的 `dedupeKey`，背景雜訊用 `priority: "low"`。 |
| `badge` | 最多 6 個字元，每秒最多更新一次。沒有內容時就清除。 |
| `eventSource.displayName` | 每種語言最多 80 字元；它說明這個狀態列屬於哪個工具。 |

**權限理由。** Manifest 沒有自由文字的理由欄位，使用者看到的是每個權限固定的白話說明，所以要證明權限合理，方法就是要得更少：用確切的主機而非萬用字元；只開啟網頁時宣告 `links.hosts` 而不是網路存取；除非主機取決於使用者，否則不要用 `userGranted`。你唯一能寫的理由是 `api.net.requestHost(host, reason)`：一句 1–120 字元的話，會顯示在確認畫面，請寫出使用者看得懂的目的（「讀取你選擇的儲存庫的發行說明」）。被拒絕後，該主機 24 小時內不會再次詢問。

zh-TW 文字請用道地的中文撰寫，不要逐字翻譯，並讓兩種語言保持同步。

## 面板頁的 Liquid Glass 與設計 token

玻璃由 Host 繪製：外框是功能層，你的頁面是**內容層**，因此：

- 不要加 `backdrop-filter` 或自己的模糊；設計規範禁止玻璃疊玻璃，請用平面填色。
- 載入 `agent-pets://plugin/_shared/tokens.css`（App 自己的 token 檔，唯讀），只用 token 設計樣式，並為獨立預覽提供後備值。頁面不會收到 App 的淺色／深色切換，永遠使用預設的深色色盤，請設定 `color-scheme: dark`。
- 頁面檢視一開始是透明的。若要獨立完整的外觀，請為 `body` 設 `background: var(--surface-panel)`（半透明深色）；不上色則會透出 Host 的表面。

| 需求 | Token |
|---|---|
| 表面 | `--surface-panel`、`--surface-raised`、`--surface-raised-hover`、`--surface-sunken`、`--surface-overlay` |
| 文字 | `--text-primary`、`--text-secondary`、`--text-muted`、`--text-danger`、`--text-success`、`--text-warning` |
| 邊框 | `--border-subtle`、`--border-strong`、`--border-accent` |
| 狀態色 | `--state-success`、`--state-warn`、`--state-error`、`--state-info` |
| 字型 | `--font-xs`（最小 11px）到 `--font-2xl`、`--weight-normal`、`--weight-medium`、`--weight-bold`、`--font-ui` |
| 間距與形狀 | `--space-1` 到 `--space-5`（4px 為基準）、`--radius-sm`、`--radius-md`、`--radius-lg`、`--radius-pill` |
| 互動 | `--hit-min`、`--focus-ring-color`、`--focus-ring-width`、`--focus-ring-offset`、`--transition-fast`、`--transition-base` |

無障礙是頁面自己的責任：文字至少 11px、提供可見的 `:focus-visible` 外框、點擊目標至少 `--hit-min`、尊重 `prefers-reduced-motion`（動畫要節制）、不要只靠顏色傳達狀態，並確保在最小寬度 320 px 下仍可閱讀。
