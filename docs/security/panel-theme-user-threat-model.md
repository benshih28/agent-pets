# 威脅模型：我的主題與主題編輯器（1.12.0）

範圍：使用者自製的面板主題（「我的主題」）、主題編輯器、`panel-theme-validate` 與 `panel-theme-user-*` IPC、`userData/panel-themes-user/` 儲存、匯出／匯入 JSON、使用者背景圖取色。規格：`docs/design/Plugin-Panel-Theme-Spec.md` §0 R20–R24。插件主題本身的威脅（封閉顏色文法、協定路由、圖片檔頭檢查）見同一份規格 §9。

## 資產與信任邊界

| 資產 | 位置 | 誰能寫 |
| --- | --- | --- |
| 主題定義 | `userData/panel-themes-user/<id>.json`（0o700／0o600） | 只有主程序，經 IPC 的面板 main frame 請求 |
| 使用者背景圖 | `userData/panel-theme-images/_user/<sha256>.<ext>` | 只有主程序（原生對話框 → 記憶體驗證 → 暫存檔 + rename） |
| 插槽選擇 | `userData/panel-theme.json` | 只有主程序 |
| 匯出檔 | 使用者在儲存對話框選的位置 | 只有主程序 |

信任邊界：設定面板渲染端 → preload → 主程序。插件 Worker、插件面板頁（獨立分區與 preload）與寵物視窗都不能呼叫這些頻道。

## 威脅與緩解

| 威脅 | 緩解 |
| --- | --- |
| 被入侵或有錯的面板渲染端送出惡意定義（CSS 注入、超大 payload、原型污染） | 每個頻道 `handleWithSenderGuard` 只接受面板 main frame；定義序列化後 ≤ 16 KiB、名稱在 NFKC 正規化之前必須是 ≤ 192 個 UTF-16 單位的字串（清理後 1–48 字元）、不接受多餘參數；定義先以封閉結構嚴格解析（固定深度，任意深的巢狀在雜湊與快取之前就以文法錯誤拒絕）（缺鍵、多鍵一律拒絕；JSON 的 `__proto__` 是自有屬性，被當成未知鍵拒絕）；每個顏色走插件主題的封閉文法並重新輸出成 `rgb(R G B / A)`；字型只能是固定的系統字型組合 id；渲染端寫入前再以白名單與逐屬性正規式檢查（與插件主題相同）。 |
| 繞過可讀性規則（把權限提示畫得看不清楚、把危險畫成綠色） | 定義在存檔與套用前都轉成 `panelThemes` 宣告，交給與插件主題完全相同的驗證器；無效的記錄不會出現在目錄，`panel-theme-slot-set` 因此回 `theme_unavailable`。版面、文字標籤、風險徽章與「按住才允許」仍由主機決定。 |
| 透過驗證請求耗盡主程序 CPU | 建議值搜尋每個候選色只重跑讀到被換的鍵的檢查，對比／亮度問題在明度上二分搜尋；每個模式最多評估 1,600 個候選色；問題數上限 64；最壞情況（每個鍵都是中灰）約 6 ms；只有解析成功的定義才以內容雜湊 LRU（32 筆）快取；主程序單執行緒、請求由單一面板發出。 |
| 路徑穿越或 symlink 讓寫入落到 userData 之外 | id 由主程序產生（`u-` + 12 個十六進位字元），IPC 只接受符合樣式的 id；目錄與檔案 lstat 檢查，拒絕 symlink 與非一般檔案；讀取 `O_NOFOLLOW` 並比對 dev/ino；寫入用同目錄的暫存檔（`wx`、0o600）再 rename。 |
| 損毀或被竄改的主題檔讓 App 無法啟動或顯示錯誤主題 | 每個檔案獨立解析；任何欄位不符（含 id 與檔名不一致、大小超過 16 KiB）就改名成 `.corrupt-<時間>` 並略過，其他主題不受影響；備份檔不符合檔名規則，不會再被讀取，只保留最新 5 份；較新版本寫入的檔案（`schemaVersion` 較大，降級後才會遇到）原封不動、不顯示、不修剪、不會被新 id 覆寫；目錄以 `opendir` 逐項掃描，上限算在主題檔與暫存檔（116 個）上、原始項目另有 4,096 的硬上限，殘留暫存檔會被移除。 |
| 修剪誤刪仍存在的主題（插槽與背景圖） | 修剪只在磁碟上確定沒有這個 id 時才清掉插槽與圖片：目錄不安全或讀不到、掃描被上限截斷時整個「我的主題」視為未知而全部保留；讀不到的檔案、較新版本的檔案、超過數量上限的檔案都算存在；仍存在的記錄即使日後被更嚴格的驗證規則拒絕也保留插槽與圖片，背景圖只依記錄本身的設定（存檔時關掉背景圖才會清掉）。 |
| 數量成長造成磁碟或記憶體濫用 | 最多 50 個主題、每個 ≤ 16 KiB；使用者背景圖沿用既有上限（每個主題每個模式 1 張、總數 ≤ 64、每張 ≤ 20 MiB）。 |
| 惡意匯入檔 | 只能經由原生開檔對話框（使用者選擇）；只讀一個 ≤ 16 KiB 的一般檔案、不跟隨 symlink、只讀一次；只接受 `format`／`schemaVersion`／`name`／`definition` 四個鍵；名稱經 NFKC、去除控制字元與角括號；通過驗證才建立新主題，絕不覆寫既有主題。 |
| 匯出洩漏個人資料 | 匯出內容只有名稱與定義：沒有 id、時間、圖片位元組、圖片檔名或任何路徑（測試檢查）；預設檔名保留各語系的字母與數字，去掉路徑分隔、控制與格式字元、Windows 保留字元與裝置名稱，長度上限 40 個碼位。寫入用暫存檔 + rename，目標若是 symlink 會被取代而不是寫穿。 |
| 取色時讀到不該讀的圖片 | 渲染端只對 `agent-pets://panel-theme/<32 hex token>` 建立 `crossOrigin` 圖片；`Access-Control-Allow-Origin` 只回給受信任的面板來源（`agent-pets://app`，開發時為 Vite 來源），而且只對字型與使用者圖片；插件分區沒有這個 host。像素只在記憶體中縮到 ≤ 128 px 取樣，不寫入任何地方。 |
| 插件得知使用者的主題或圖片 | 插件主題 API（`--ap-*`、`api.theme`）只回報顏色、圓角、字族與字級倍率，與插件主題相同，不含擁有者、主題 id、名稱或圖片；插件不會收到「我的主題」的新增、修改、刪除事件或任何識別值；只有在套用中的主題被存檔而顏色改變時，`theme.onDidChange` 會收到新的顏色（與切換主題相同）。 |
| 刪除後殘留 | 刪除主題後，修剪會清掉指向它的插槽（該模式回到內建）與它的圖片項目與檔案；啟動時的孤兒清掃保留 `_user` 目錄但刪除沒有被引用的檔案。 |

## 殘餘風險

- 匯出與匯入的位置由使用者在原生對話框決定；寫到使用者自己選的位置屬於使用者意圖。
- 只在 macOS 驗證；Windows 的檔案權限（0o700／0o600 在 NTFS 上不適用）沿用 userData 的使用者層級 ACL。
- 驗證建議值以 OKLCH 明度搜尋，找不到時（例如前景與背景都被鎖死）不提供建議，使用者需自行調整。
