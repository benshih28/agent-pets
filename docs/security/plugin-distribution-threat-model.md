# 插件散佈威脅模型

## 範圍與安全目標

本文件涵蓋線上插件目錄、插件下載、作者簽章與既有安裝流程的信任邊界。目標是在不把目錄或下載內容視為可信的前提下，避免內容遭替換後靜默安裝、限制降版與插件識別混淆，並讓使用者能看見未簽章或金鑰變更風險。

線上功能預設關閉。啟用後，只有使用者開啟目錄或要求檢查更新時才連線；每日檢查選項預設關閉，更新只提示，不自動下載或安裝。目錄、下載內容、manifest、簽章檔及其中的文字都視為不可信輸入。

## 資產

- 插件套件的完整性，以及作者公鑰與插件識別碼之間的本機信任綁定。
- 插件安裝目錄、插件登錄資料、使用者已授予的權限與更新決定。
- 宿主的檔案系統、IPC、網路能力及由既有 Plugin Host 保護的主程序能力。
- 使用者對插件作者、版本、簽章狀態與權限變更的正確理解。
- 網路請求的最小化；目錄與下載流程不應附帶 Cookie，也不應傳送使用者資料。

## 攻擊者與能力

- **惡意插件作者：** 可發布惡意 manifest、套件或簽章內容，並可能持有自己的簽章私鑰。
- **目錄遭入侵者：** 可修改公開目錄項目、指向其他套件，或以惡意文字混淆使用者。
- **網路中間人或遭入侵的下載來源：** 可嘗試替換回應、操控重新導向或提供超大／格式錯誤的資料。
- **插件 ID 搶註者：** 可先發布與既有插件相同 ID 的項目，或利用名稱相似混淆使用者。
- **作者金鑰失竊者：** 可在私鑰失竊期間，以受信任金鑰簽署惡意更新。
- **本機使用者：** 可自行安裝未簽章插件或接受明確的金鑰變更；此選擇可能降低保護程度。

本模型不假設公開目錄能證明作者的法律身分，也不涵蓋 GitHub 帳號、公開 repo 權限或使用者端點本身已完全失陷的情況。

## 信任邊界

1. **目錄 → Main：** 目錄是未驗證的網路輸入。必須逐欄位檢查型別、長度、格式及項目上限；一筆錯誤資料不得使其他有效項目一併失效。目錄文字以純文字呈現，不能提供可擴充網路主機清單的能力。
2. **下載來源 → Main：** 只有 Main 讀取目錄與下載套件。請求限 HTTPS、443 與程式內固定的允許主機；重新導向每一跳都要重新驗證主機及 DNS/IP，封鎖 loopback、私有、link-local 等非公開位址，不帶 Cookie，並設大小與逾時上限。
3. **套件 → 安裝器：** 套件內容需先驗證大小、SHA-256、簽章和 manifest，再交給既有嚴格 archive guard 與安裝計畫。不得在驗證前解壓寫入正式插件目錄。
4. **作者金鑰 → 本機信任：** 首次簽章安裝採 TOFU，使用者首次接受時把該插件公鑰指紋綁定在本機。此綁定表示「之後沿用同一金鑰」，不代表已核實作者真實身分。
5. **插件 → Plugin Host：** 散佈與簽章驗證不取代既有 Plugin Host 的權限、IPC、網路與資源限制。簽章有效只證明套件由持有該私鑰的一方簽署且內容相符，不能證明程式安全。

## 威脅與控制

| 威脅 | 控制 | 殘餘風險 |
|---|---|---|
| 目錄被竄改，替換描述、版本或下載位置 | 目錄 JSON 嚴格驗證並設總大小、插件數、版本數上限；下載 URL 僅接受固定允許主機；目錄宣告的 SHA-256、大小與下載內容比對；若有目錄公鑰指紋，需與套件簽章指紋一致。 | 公開目錄沒有獨立的目錄簽章或透明日誌。遭控制目錄的人仍可隱藏項目、改寫描述或造成拒絕服務；hash 與目錄同時遭改寫時，仍須靠作者簽章及使用者信任確認保護完整性。 |
| 套件下載被替換或傳輸內容損壞 | HTTPS、固定 host allowlist、逐跳 redirect 驗證、DNS/IP 封鎖、逾時與大小上限；下載後驗證目錄中的大小及 SHA-256；簽章 payload 涵蓋除 `signature.json` 外的所有套件檔案。 | 若目錄和發布來源同時被控制，未簽章套件仍可能被替換；SHA-256 本身不是作者認證。已失竊的作者私鑰可簽署替換內容。 |
| 降版攻擊 | 更新候選只接受高於已安裝版本的版本；降版仍使用既有明確確認流程，不可由背景檢查自動套用。 | 使用者可手動接受降版；目前的版本比較與 prerelease 規則仍須由實作測試固定，版本字串錯誤不得放寬成降版安裝。 |
| 插件 ID 搶註或名稱仿冒 | manifest 的 ID 格式驗證；安裝與更新以 ID 為識別，顯示作者、ID、版本和簽章狀態；首次簽章接受時綁定指紋，後續金鑰變更預設取消並顯示新舊指紋。 | 沒有中央 ID 登記或作者身分驗證。攻擊者可能先註冊未被使用的 ID，或用相似名稱誤導使用者；首次 TOFU 的選擇本身仍可能受釣魚影響。 |
| 作者私鑰遺失 | 不提供宿主代替作者恢復私鑰；新金鑰視為信任變更，使用者必須看到新舊指紋並明確確認。 | 原金鑰無法再發布可自動信任的更新；使用者可能需重新評估新金鑰，無法確認新金鑰是否屬於原作者。 |
| 作者私鑰外洩 | 更新時固定比對已信任指紋；更換金鑰需明確確認，預設取消；簽章驗證失敗即拒絕。 | 攻擊者可在受信任私鑰撤銷前簽署惡意版本。此設計沒有線上撤銷服務；使用者需依可驗證的外部通知決定是否接受輪替。 |
| 未簽章插件 | 維持可選擇安裝，但在目錄、安裝確認及插件列表明顯標示未簽章；已簽章插件更新成未簽章時要求明確確認。 | 未簽章內容沒有作者來源驗證；使用者接受後只能依賴 archive guard、manifest、權限提示與既有 Plugin Host 隔離。 |
| 重新導向至不允許的主機或內部網路 | 只允許固定 GitHub host；每一跳重驗 HTTPS、主機、443、DNS 結果和 IP 黑名單；不跟隨跳至未宣告或不允許的目的地。 | DNS 與網路環境可能在檢查與連線間改變。實作需避免檢查後改以未驗證 URL 連線，並用注入式網路測試覆蓋 redirect。 |
| 超大檔案、解壓縮炸彈或惡意 archive 路徑 | 目錄、下載、壓縮檔、解壓後總量、單檔與檔案數皆設上限；SHA-256/size 通過後仍須經嚴格 archive guard；拒絕路徑穿越、重複路徑、非允許副檔名及超限內容。 | 壓縮格式解析器仍可能有資源消耗或實作缺陷；上限降低但不能消除所有解析器漏洞。錯誤或超限套件必須失敗關閉且不得部分安裝。 |
| 惡意套件利用有效簽章取得過度能力 | 簽章資訊與權限變更在安裝確認中顯示；新增權限沿用重新同意；安裝仍走現有 Plugin Host 限制。 | 簽章不等於安全審核。已同意權限內的惡意程式仍可能造成使用者可見的損害；簽章不能阻止作者自行發布惡意程式。 |

## 安全決策

- 所有網路輸入與套件欄位都採失敗關閉；不能解析或不能驗證時，不安裝該筆資料。
- `invalid` 簽章拒絕安裝。TOFU、金鑰變更、已簽章轉未簽章都不得隱式接受。
- 目錄提供者不能增加允許下載的 host，也不能指定回報連結目的地。
- 線上檢查只取得資訊並提示；下載、更新、權限變更及信任變更都由使用者明確確認。
- 目錄與下載依賴以注入方式測試；測試與隔離 Electron 驗收不得連到真實 GitHub。

## 待決問題

- 目錄有重複插件 ID 時，是否整份目錄拒絕，或只丟棄重複 ID 的項目？在規則明確前，採拒絕歧義項目的保守策略，不任意選一筆。
- TOFU 首次確認目前沒有獨立的作者身分或目錄治理證明；是否要在未來版本加入簽章撤銷或目錄透明度機制，需另行決策。
- 插件版本的 semver/prerelease 正規化與最高版本選擇規則，需由 P17.2/P17.3 契約及測試明確固定；本文件不自行定義相容性細節。
